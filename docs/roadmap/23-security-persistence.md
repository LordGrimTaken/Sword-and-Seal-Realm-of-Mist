# Security, Accounts & Persistence

1. **Scrypt parameter hardening** — Raise the account scrypt cost factor (N/r/p) and store a fresh random salt beside each hash in the `node:sqlite` accounts table, so a leaked `jiuzhou.db` cannot be brute-forced across the 4-64 character password space.
2. **Argon2id upgrade path** — Add an on-login rehash that transparently migrates existing scrypt hashes to Argon2id, so the launcher `/api/auth/*` flow and the in-game `login` `pw` path both move to a stronger KDF without forcing a password reset.
3. **Weak-password rejection at register** — Keep the 4-64 char rule but refuse all-whitespace or single-repeated-character passwords with the existing "Password must be 4 to 64 characters." style error, slowing dictionary attacks on `/api/auth/register`.
4. **Common-password blocklist** — Check new passwords against a small bundled list of common passwords and reject matches at register, returning the same `409` JSON the account API already uses so brute-force signups are throttled early.
5. **Password redaction middleware** — Extend the "passwords are never logged" rule with a redaction layer over every request/response and error path, so a failed `/api/auth/login` never writes the `pw` field into a log line.
6. **Token secret key rotation** — Replace the single `TOKEN_SECRET` / `token.secret` with a key-id plus rotated HMAC secret ring, so a leaked signing secret can be retired without invalidating every live 300-second launcher token at once.
7. **Token bound to launcher device** — Bind each 300s token's `jti` to the launcher install/device id at issue and verify it at the WebSocket `login`, so a stolen token cannot be replayed from a second machine.
8. **Strict token expiry and one-time use** — Keep the 300s single-use token but enforce `exp` and the burned-`jti` check strictly at game `login`, rejecting reuse with the existing "Session expired. Sign in again from the launcher." text.
9. **Auth audit trail in sqlite** — Append a row per successful and failed auth (name, hashed IP, time, result) to a new `auth_log` table, so the moment the 5/60s login limiter trips there is a concrete record to review.
10. **New-device sign-in notice** — When a successful login arrives from a new IP or device for an account, emit a System `chat` line on the next game entry ("A new device signed in to your account.") so a hijacked credential is visible to its owner.
11. **Password reset via recovery code** — Since there is no email, generate a one-time recovery code at register for the launcher to display and store, and let a lost password be reset through a `/api/auth/reset` that consumes that code.
12. **Delete confirmation via password or recovery code** — Require re-entering the current password or a one-time recovery code before any account delete or reset, so a hijacked token alone cannot erase the account.
13. **Name normalization and homoglyph rejection** — Normalize account names to the canonical NOCASE form already used by the characters table and reject lookalike glyph substitutions, so two visually identical names cannot be registered to confuse other players.
14. **Launcher session file hardening** — Tighten the existing `sword-and-seal-session-*.json` (mode 0600, 2-minute `createdAt`) by binding it to the launcher PID and deleting it on spawn, closing the window where a leftover file is read by a second process.
15. **Force WSS for game connections** — In launcher and packaged mode refuse `ws://` game URLs and require `wss://`, so Cloudmist Valley traffic is never sent in clear text in production even when a config override points at plaintext.
16. **HSTS on the Cloudflare Workers site** — Emit a `Strict-Transport-Security` header from the Workers website so the launcher download page and account pages never downgrade to HTTP after the first visit.
17. **TLS minimum version at the Workers edge** — Configure Cloudflare to require TLS 1.2+ and a modern cipher set for `play.swordandseal.com` and `dl.swordandseal.com`, protecting the account API and the release downloads in transit.
18. **Certificate pinning in the Electron launcher** — Pin the `apiBaseUrl` and `releaseBaseUrl` TLS certificate or public key inside the launcher, so a rogue CA cannot serve a fake `latest/manifest.json` that ships a tampered client.
19. **Manifest SHA-256 verification everywhere** — Extend the existing manifest `sha256` check (already applied to game files) to the launcher's own update payload and `news.json`, so an R2 or CDN compromise is caught before anything is installed.
20. **Signed release manifest** — Publish an Ed25519 signature beside `latest/manifest.json` and verify it in the launcher, so only the build pipeline's key can bless a new version and a defaced R2 object cannot push a backdoored game.
21. **Encrypt the local sqlite at rest** — Apply SQLCipher or an equivalent behind the existing `db.ts` layer with a key derived from a server env secret, so a stolen `jiuzhou.db` file does not expose coin, jade, quest, or gear state.
22. **Remember-me name in the OS keychain** — Store the launcher's remembered account name in the OS credential store (Keychain / Credential Manager) instead of the plaintext settings file, since it is the only persistent account hint on disk.
23. **PLAY-time token in the OS keychain** — Move the PLAY-time password/token handoff to the OS credential store rather than main-process memory plus a temp file, shrinking the lifetime a secret sits in a filesystem file.
24. **Secrets never in argv or env** — Audit the `--launcher-session`, `JZ_SERVER_URL`, and `SWORD_AND_SEAL_LAUNCHER` paths so no token or password ever appears in `ps`, argv, or env, closing the leak the launcher docs already warn about.
25. **Cloud save write-through on autosave** — Persist characters, quests, items, wallet, and daily tables in one transaction on the existing 30s autosave tick, so a crash mid-save cannot leave the wallet claimed while the daily stays unflipped.
26. **Cross-device resume by account name** — Make the account (not the machine) the save key, so signing in from a second PC through the launcher loads the same level-20-capped character, gear, 30-slot bag, and daily progress.
27. **Device list and logout-elsewhere** — Add a per-account active-session list that lets a player revoke other sessions, so a forgotten launcher on a shared PC cannot keep farming the character's daily board.
28. **Same-name concurrent login policy** — Formalize the existing duplicate-online-name rejection with a distinct System `chat` line ("Signed in elsewhere."), so cross-device login behaves predictably instead of silently failing.
29. **Save version stamp on every row** — Add a `schema` version column to the characters, quests, items, wallet, and daily tables and stamp it on write, so a future cross-device sync can detect stale local versus server state.
30. **Cloud save conflict resolution** — When two devices raced a change (a daily `claim` and a `/talk` turn-in), prefer the server's last write with a one-line System notice, so a second device never overwrites a fresh Stone Guardian clear.
31. **Offline progress merge rejected** — Because the client is replaceable and thin, forbid any client-supplied "offline progress" and only accept server-authored state, preventing a forged save upload from minting coin or jade.
32. **Save export/import in the settings panel** — Reuse the versioned `jz.settings.v1` export/import text flow to let a player back up their character state manually, matching the existing settings export UX.
33. **Character snapshot for support** — Add an operator endpoint that dumps one character's quests, gear, wallet, daily, and titles as JSON for support tickets, without exposing any other player's rows.
34. **Soft-delete with retention grace period** — Flag a deleted account's rows as deleted (not purged) for a grace window before hard delete, so a mistaken account deletion can be reversed from backup.
35. **Versioned schema migrations in `db.ts`** — Replace the ad-hoc startup `ALTER TABLE` edits with a numbered, in-transaction migration list, so the `mei`, `wallet`, and `daily` column additions become replayable and testable.
36. **Migration preflight backup** — Before running any startup migration, copy `jiuzhou.db` to a timestamped `data/backups/` file, so a failed `ALTER TABLE` on the live single-file DB can be rolled back.
37. **WAL mode and busy timeout** — Enable SQLite WAL with a sane busy timeout on `node:sqlite`, so the 20Hz tick's writes and the account API's auth writes on separate connections do not collide and corrupt the single DB.
38. **Foreign keys and check constraints on** — Enable `PRAGMA foreign_keys` and link wallet, daily, and items rows to the character row, so a half-written character can never strand orphaned coin or a claimed daily.
39. **Atomic multi-table writes** — Wrap the existing daily-claim (flip `claimed` plus save wallet together) in one `BEGIN...COMMIT`, so the economy module's separate connection cannot commit a reward without the matching wallet update.
40. **Scheduled full backup** — Add a configurable interval (e.g. hourly) that copies `jiuzhou.db` to `data/backups/` and prunes old copies, distinct from the 30s autosave which is a checkpoint, not a backup.
41. **Point-in-time WAL snapshot** — Use the WAL to take consistent backups without stopping the 20Hz tick, so backing up a live server does not capture a torn write mid-combat.
42. **Backup integrity checksum** — Store a SHA-256 of each backup file alongside it and verify on restore, so a truncated copy cannot silently load as a "recovered" world.
43. **Automated restore drill** — Add a script or test that restores the newest backup into a temp DB and boots the bot suite against it, proving backups are restorable rather than merely present.
44. **Migration test coverage in `npm test`** — Extend the suites to create a DB at each old schema version and migrate it forward, so the v1 to v3 quest-shift and item-name rewrite stay covered as more columns land.
45. **Startup migration idempotency** — Make every migration check existence before altering and track it in a `schema_migrations` table, so a restart never re-adds a column and crashes on a duplicate.
46. **Data-directory permissions** — Set restrictive permissions on `data/` (the `jiuzhou.db`, `token.secret`, and backups) so only the game server process can read them, matching the launcher session file's 0600 intent.
47. **Account deletion endpoint** — Add `POST /api/auth/delete` (password or recovery code required) that soft-deletes the account and its character, fulfilling the right-to-erasure the game currently lacks.
48. **Character reset/reroll** — Add an explicit reset that wipes quests, items, wallet, and daily but keeps the account, so a player can start over without a second account and without being stuck with a fixed-at-creation class.
49. **Data export endpoint** — Add `GET /api/auth/export` returning the player's own characters, gear, quests, wallet, daily history, and titles as JSON, so GDPR portability can be honored with server-owned data.
50. **Retention schedule for logs** — Define and enforce a retention window for `auth_log`, chat history, and request logs (e.g. 90 days) and purge them automatically, so the server is not an unbounded store of personal data.
51. **GDPR self-serve page** — Add an English-only account management page on the Cloudflare Workers website that calls the delete/export endpoints, giving players a self-serve path without emailing support.
52. **Analytics opt-out by default** — Default any future telemetry to off and expose an opt-out flag in the settings panel, respecting the privacy and accessibility posture the rest of the game follows.
53. **Log redaction of other players' data** — When a support export or backup is shared, redact other players' names and IPs so a single characters-row dump never leaks the whole zone's roster.
54. **Privacy note in the launcher** — Add a short plain-English privacy note (what is stored, retained, and deletable) to the launcher sign-in card, so the account flow states its GDPR posture up front.
55. **IP logging minimization** — Store only a hashed or truncated IP for rate limiting and auth audit rather than full addresses, so the 5/60s limiter still works while the stored data is less identifying.
56. **Right-to-erasure cascade** — When an account is deleted, cascade the soft-delete to quests, items, wallet, daily, titles, and the auth audit trail, so no orphan row re-appears on a later migration.
57. **Server-authoritative position validation** — Since the server already owns position, validate every movement and dodge delta against `PLAYER_SPEED` and the 6-unit dodge per tick and rubber-band impossible moves, closing the no-collision gap for speed hacks.
58. **Dodge and skill rate limiting** — Cap dodge and skill-cast messages per tick to the 1.5s dodge cooldown and each skill's cooldown plus 0.3s GCD, so a macro cannot spam Heaven-Splitting Strike or dodge-roll faster than `data.ts` allows.
59. **Qi-cost and cooldown sanity checks** — Reject any cast whose Qi cost is zeroed or whose cooldown is shortened client-side by re-checking the authoritative 100-point pool and 10/s regen on the server, mirroring the existing not-enough-Qi refusal.
60. **Wallet and item integer overflow guards** — Validate that coin, jade, and item quantities stay within bounded integers and never go negative in the `wallet` and `items` tables, so a crafted `buy`/`sell`/`craft` message cannot mint or underflow currency.
61. **Item duplication prevention** — Tie every `sell`, `craft`, and `equip` to a real owned stack quantity and decrement it in the same transaction as the grant, so a racing duplicate message cannot clone a Guardian Core or Jade Scale.
62. **Quest progress tamper resistance** — Keep quest progress (stage, status, progress2) server-derived from kills and loot only, never from a client-supplied number, so the Elder Lin 4-quest chain and Mei's errand cannot be auto-completed.
63. **Daily claim idempotency hardening** — Strengthen the existing one-time `claim` guard with a per-task monotonic claim id in sqlite, so replayed or duplicated `claim` messages grant exactly once even across a server restart.
64. **Boss telegraph and enrage validation** — Validate that Stone Guardian damage only lands inside the reported telegraph radius/delay and that the enrage multiplier is server-applied, so a client cannot skip the 3-phase fight.
65. **Chat text sanitization on the client** — Since the server notes chat is not HTML-escaped, render all chat and name text as text nodes with escaping on the client, so a `<` in a name cannot inject DOM into the paper-scroll chat panel.
66. **JSON input size and depth limits** — Enforce the existing 2KB input-frame cap plus a max JSON nesting depth and key count on every WebSocket message, so a crafted deep object cannot stall the server's parse loop mid-tick.
67. **Message type allowlist** — Reject any WebSocket message whose `t` is not in the known protocol set (`input`, `chat`, `login`, `dodge`, `claim`, `equip`, `craft`, `buy`, `sell`, `npc`, `title`, and the rest), so unknown types fail closed.
68. **Session replacement, not duplication** — Ensure a second successful `login` for the same name always replaces (never duplicates) the session and invalidates the old socket, preventing session fixation and double-spending the one-time token.
69. **Client bundle integrity check** — Verify the client bundle hash served to the browser matches the release manifest, so a tampered `app.js` cannot run and the Web client trusts the same SHA-256 chain the launcher already uses.
70. **Anti-cheat telemetry in `/health`** — Surface counts of rejected casts, dodges, and movement anomalies in the `/health` diagnostics, giving operators a live signal that a cheat or bug is being attempted.
71. **Per-IP and per-name rate limit parity** — Finish the trusted-proxy support noted in the README so the 5/60s login and 10/min register limits see the real client IP behind Cloudflare instead of one shared proxy IP for everyone.
72. **Chat rate limit and flood protection** — Extend the existing token-bucket rate limit to a per-player chat bucket that also caps message length and repetition, so a bot cannot spam the zone-wide `chat` channel in Cloudmist Valley.
73. **Mute and temporary ban** — Add operator actions that mute a name for a duration or ban it outright, stored in sqlite and enforced at `login`, so abuse can be stopped without restarting the 20Hz loop.
74. **In-game block/ignore list** — Let a player ignore another name so their chat and any future trade or party requests are filtered client- and server-side, giving a self-serve tool against harassment.
75. **Report command with evidence** — Add a `/report <name> <reason>` command that writes a bounded row to sqlite with a timestamp and both names, feeding an operator review queue rather than an automated punishment.
76. **Name profanity and CJK filter** — Extend the existing English-only rule and `check:english` with a small profanity list and CJK rejection on account and character names, so offensive or hanzi names are refused at register.
77. **Griefing limits around boss and rare spawns** — Since Stone Guardian and Old Whisker credit goes to threat-holders, add a minimum-contribution rule so a level-20 can neither deny nor monopolize the boss kill against fresh players.
78. **Kill-stealing and mob-leash fairness** — Keep mob aggro, leash, respawn, and drop credit server-owned and deterministic, so a faster player cannot chain-pull the 27 mobs away from slower ones in the shared zone.
79. **Multiple-account and daily-board abuse detection** — Detect many accounts created from one IP and shared-name patterns, and cap daily-board claims to one per character per day, so a player cannot farm jade across throwaway accounts.
80. **Operator admin authentication** — Protect any future admin, mute, ban, or restore endpoints with a separate operator credential and least-privilege scope, so the account API and game server do not share one mutable secret.
