# Testing, Tooling & CI/CD

1. **Extract pure sim functions from `server.ts` into unit-testable modules** — the Qi regen, dodge resolution, and telegraph damage rules currently live inside the 20Hz tick loop, so pulling them into `game/combat.ts`, `game/dodge.ts`, and `game/economy.ts` pure functions lets tests call `applyQiRegen` or `resolveTelegraph` directly without booting a WebSocket server or a temp sqlite DB.
2. **Add table-driven unit tests for `telegraphContains`** — enumerate circle/cone/line/beam edge cases (query point at the cone apex, across-axis, just beyond `len`, a rotating beam mid-`sweep`) against hand-computed answers so the shared hit-test stays the single source of truth for both server damage and client prediction.
3. **Unit-test the Qi economy model** — assert the 100-point pool, 10/s regen, the 15-Qi dodge cost, and the 1.5s dodge cooldown with a fixed virtual clock, so regressions in the "empty Qi" or dodge-spam paths surface without a socket round-trip.
4. **Unit-test the dodge i-frame window** — verify a Stone Guardian slam that lands during the roll emits `dodged` and one that lands after the window resolves to real `damage`, exercising the `game/dodge.ts` rules directly rather than only through the boss bot.
5. **Property-test the movement integrator** — feed random `input` dx/dz sequences and assert the player position stays inside the 200x200 Cloudmist Valley bounds and speed never exceeds `PLAYER_SPEED` (6), complementing the hacker bot's clamp check with exhaustive random inputs.
6. **Unit-test mob spawn distribution against `MOB_SPAWNS`** — assert the 27 mobs across Bamboo Spirit, Fox Spirit, Jade Serpent, Lotus Toad, Stone Hound, Old Whisker, and Stone Guardian are placed inside the zone, and that Jade Serpent points stay >=35 from the spawn plaza and >=10 apart, turning the geometry checks in `bots.ts` into a fast static test.
7. **Unit-test the Stone Guardian phase machine** — drive a fake boss entity through >50% (slam circles), <50% (scatter ring of 3), <25% (rotating rune beam), and enrage thresholds and assert the correct `telegraph` shape, `sweep`, `lead`, and `delay` is scheduled per phase.
8. **Unit-test gear stat summation** — build a `GearStats` from the 6 slots (weapon/head/body/boots/charm/pendant) with mixed common/fine/rare/epic rarities and assert atk/hp/crit/def fold correctly, including the def percentage and the crit 0.02 = +2% scaling.
9. **Unit-test the 30-bag-slot stack cap** — push items past 99 per stack and 30 distinct stacks and assert the server clamps and refuses overflow, mirroring the existing `Bamboo Fiber` 150->99 check in `bots.ts` but as a pure `inventory.ts` function.
10. **Unit-test recipe resolution in `contentdb.ts`** — feed each of the 10 recipes its exact materials and assert the craft succeeds, and that a missing or extra material fails, so the recipe table never drifts from the craft view the NPC panel renders.
11. **Unit-test wallet invariants in `economy.ts`** — assert coin/jade never go negative, buy/sell prices match the `BuyView`/`SellView` the peddler shows, and a daily-board `claim` pays exactly once per task per UTC reset.
12. **Unit-test the daily board reset boundary** — freeze a fake clock just before and after the UTC reset and assert `daily` re-issues tasks and `resetIn` recomputes, avoiding a flaky test that depends on wall-clock midnight.
13. **Unit-test Elder Lin's chain stage machine** — walk a fake character through Quest 1 (Clear 5 Bamboo Spirits), the Fox Spirit hunt, Cleanse the Pond (4 Jade Serpents + 2 Jade Scales), and Defeat the Stone Guardian, asserting progress counters, auto-accept, and turn-in rewards at each step without a live fight.
14. **Unit-test side-quest idempotency** — assert Mei's Wicks errand rewards exactly once, and that Wu/Tao/Hao/Fen quests do not double-pay on repeated `/talk`, with accepted/completed states round-tripping through `CharacterDb`.
15. **Unit-test the sqlite migration ladder in `db.ts`** — apply each `ALTER TABLE` migration to a fixture DB from the previous schema version and assert existing rows survive and new columns default correctly, generalizing the in-line `mei` migration check from `bots.ts`.
16. **Add a protocol-frame fuzzer harness** — feed thousands of mutated `ClientMsg` JSON frames (wrong `t`, `1e999` numbers, nested objects, binary blobs) and assert the server survives and only closes the offending socket, expanding the 11-case fuzz block in `bots.ts` into a seeded randomized sweep.
17. **Property-fuzz `telegraphContains` against an independent formula** — generate random circle/cone/line telegraphs and random query points and check containment against a separately derived analytic formula, guarding the shared hit-test against sign and angle regressions.
18. **Fuzz the login/password path in `auth.ts`** — hammer `login` with empty names, 1-char and 65-char passwords, unknown-name registration vs wrong-password rejection, and launcher-token expiry, asserting the rules hold and no crash leaks a session.
19. **Fuzz `cast` with out-of-range target ids, negative skills, and NaN tx/tz** — assert only valid skill 1-4 casts emit `cast` events and invalid ones are rejected with a range/error, extending the hacker bot's cooldown/range checks into a randomized sweep.
20. **Add a structured property test for interest management** — randomly teleport a bot around the zone and assert no entity beyond `INTEREST_RADIUS` (60) is ever sent and every `gone` id was previously known, covering what `bots.ts` samples manually at two fixed points.
21. **Fuzz the sqlite persistence layer with concurrent saves** — open several `CharacterDb` writers for the same character and assert no deadlock, corruption, or duplicate row, since node:sqlite `DatabaseSync` is single-connection and races are a real risk on autosave.
22. **Seed the fuzz corpus with recorded real frames** — capture the login/cast/equip/craft/buy/claim frames from a soak run and replay them as mutation seeds, so the fuzzer reaches deep protocol paths instead of only the login handshake.
23. **Run `ui-test.mjs` across a device matrix in CI** — execute the existing Playwright suite at 1280x720, 1920x1080, and a narrow 360x640 so the paper-scroll HUD overlap, wallet pill, and quest tracker are verified at every supported viewport.
24. **Add a photosensitive-safety screenshot pass** — script Playwright to capture every Stone Guardian telegraph (slam circle, scatter ring, rotating beam) and assert per-frame brightness/flash deltas stay under a threshold, verifying the photosensitive-safe pledge for the boss fight.
25. **Assert the colour-assist and high-contrast settings visually** — toggle `settings.ts` colour-assist and high-contrast in headless Chromium and diff screenshots of the ink/vermilion/jade HUD to prove the palette changes and stays legible for low-vision players.
26. **Assert reduce-motion disables screen shake and dodge-roll camera** — enable reduce-motion and capture the roll and slam VFX frames to verify no large translate/scale deltas, keeping motion-sensitive players safe during the Jade Serpent bite and Stone Guardian slam.
27. **Add ARIA/focus-order checks to `ui-test.mjs`** — enumerate the tab order and `aria-*` attributes on the login, bag, gear, and NPC dialog panels and assert every control is reachable and labelled, turning the accessibility priority into a tested contract.
28. **Extend the headless e2e to the full Elder Lin chain** — drive the browser client from spawn (0,-80) through Bamboo Spirit, Fox Spirit, Jade Serpent, and Stone Guardian kills and assert the quest tracker and toast fire, closing the gap between the WS-bot scenario and the real client UI.
29. **Headless-test the gear/craft/shop flow end-to-end** — in Chromium, open the gear panel, equip a drop, open the craft list at the NPC, craft one of the 10 recipes, buy and sell at the peddler, and assert `gear`, `inv`, and `wallet` messages update the rendered UI.
30. **Headless-test the minimap, world map, and atlas places** — click through the world map and atlas in Playwright and assert each discovered Cloudmist Valley place pins correctly, so the `poi`/`prog` views and their ink-wash icons render as designed.
31. **Add a reconnect/outage test at the browser level** — restart the server under a connected page (as `ui-test.mjs` already does once) and assert the client re-logs in, restores inventory/wallet/quests from sqlite, and clears the reconnecting overlay without leaking console errors.
32. **Headless-test the login screen's English-only and password rules** — drive the login form to reject empty/too-short passwords and non-ASCII names, and assert every label and error string renders English with zero hanzi, tying the client UI to the server's `auth.ts` rules.
33. **Parameterize the soak harness to scale bot count** — make `soak.ts` accept `SOAK_BOTS=50/100` and ramp the three classes evenly so the single-process server's tick budget, snapshot fan-out, and sqlite write path are measured under real concurrency, not just 3 bots.
34. **Add a spawn-storm load test** — have N bots log in and teleport to the same pond/grove coordinates simultaneously and assert the server keeps the 20Hz tick and 8-12 snap/s window without dropping snapshots for slow sockets.
35. **Add a boss-arena stress test with many spectators** — park 50 bots inside `INTEREST_RADIUS` of the Stone Guardian while one trio fights it, and assert beam/slam telegraph events reach every spectator within the tick budget, exercising the worst-case fan-out.
36. **Record and fail on RSS growth plus a write-rate ceiling in the soak** — keep the existing <30% RSS-growth assertion and add a sqlite writes-per-second and entity-count ceiling, so a slow leak in autosave or mob AI is caught before it ships.
37. **Add latency/jitter injection to the bot harness** — delay or reorder `snap` frames per bot and assert the server's `droppedSnaps` logic and the client's interpolation stay consistent, since the game runs on JSON full-state snapshots over the public WebSocket.
38. **Add a reconnect-churn load test** — have bots connect, complete a cast, and drop every few seconds and assert the server reclaims entities and no "heartbeat timeout"/"terminating client" errors accumulate in the log.
39. **Turn the bot harness into a reusable CLI** — expose the `Bot` class from `bots.ts`/`soak.ts` as a script that runs a named scenario (`--scenario boss`, `--scenario quest`, `--scenario craft`) against any `BOT_URL`, so a developer can point it at a deployed Fly.io server for a manual smoke run.
40. **Add a deterministic replay mode to the load harness** — capture the input/event stream from a soak run and replay it with a fixed seed, so a flaky server crash can be reproduced tick-for-tick instead of hunted by hand.
41. **Split the server CI into a fast unit job and a slow integration job** — run the pure `telegraphContains`/economy/gear unit tests in seconds on every PR and gate the ~20-minute `bots.ts` + soak suite on merge to main, so small PRs don't wait on the boss fight.
42. **Add a `test:unit` script to `server/package.json`** — introduce a real unit test runner (node:test with `tsx`) alongside the script-based `run-all.mjs`, so the game-logic modules get coverage reporting instead of only the end-to-end scripts.
43. **Add coverage reporting gated at a floor** — emit lcov from the unit tests for `combat.ts`, `dodge.ts`, `economy.ts`, `gear.ts`, and `quests.ts`, and fail CI when line coverage drops below a set percentage, keeping the fast paths honest.
44. **Add a matrix CI job for Node 22 LTS across macOS/Windows/Ubuntu** — the known limitation "Windows/macOS untested" is a CI gap; run the server test suite and launcher tests on all three OSes so `server-process.cjs` spawn and path handling are proven cross-platform.
45. **Add a Cloudflare Workers CI job with `wrangler`** — typecheck and unit-test `site-worker` and `dl-worker` and run `website/scripts/test.mjs` and `linkcheck.mjs` on every site change, so the R2 download host and marketing pages are covered like the game server.
46. **Add a release-pipeline canary stage** — after `make-release.mjs` builds, boot the packaged server in CI, run the bot smoke scenario against it, and only then allow `publish-release.mjs`, so a broken bundle cannot reach the R2 download host.
47. **Publish soak results as a CI artifact and trend chart** — save the soak `[time to kill]` table and RSS/entity samples as JSON and fail the merge when TTK for a Sword Cultivator vs Bamboo Spirit or the Stone Guardian regresses beyond a tolerance.
48. **Add a scheduled nightly soak job** — run `soak.ts` at 180s or longer on a cron against the latest main to catch leaks and drift that PR-sized runs miss, and alert on RSS growth or dropped snapshots.
49. **Add a deterministic seed to every bot/scenario** — make `bots.ts`, `telegraph.ts`, `dodge.ts`, and `soak.ts` accept a `SEED` that fixes loot rolls, mob aggro, and crit so CI never flakes on the 70% drop chance or a crit timing.
50. **Add an ESLint/typecheck gate for `shared/protocol.ts` consumers** — the protocol is imported by server, client, and bots; CI must typecheck all three against the same file so a field rename breaks loudly at PR time, not at runtime in the client.
51. **Add a live inspector route to the server behind `TEST_MODE`** — serve a read-only `/debug` endpoint listing connected sockets, their class, tick, and last input, so a developer can watch a stuck bot or leaked connection without a debugger.
52. **Add an in-server tick-budget profiler** — instrument each 20Hz tick with per-phase timings (mob AI, telegraph resolution, snapshot serialization, sqlite autosave) and expose them on `/health` or `/debug`, so a hot frame is attributable to a phase instead of guessed.
53. **Add a replayable event log behind an env flag** — record every inbound `ClientMsg` and outbound `GameEvent` with tick stamps to a rotating file so a reported bug (e.g. a dodge not negating a Jade Serpent bite) can be replayed exactly.
54. **Add a `/health` latency histogram** — extend the current `/health` JSON with p50/p95/p99 tick-to-tick and snapshot-send latencies, so the soak harness and Fly.io health checks can alert on tail latency rather than just "alive".
55. **Add a client-side debug overlay gated by `?debug=1`** — surface the existing `debug=1` flag with a paper-scroll panel showing snapshot rate, interpolation buffer depth, RTT, and Qi/cooldown, so tuning the client netcode does not require guessing.
56. **Add a protocol inspector that pretty-prints live frames** — in the debug overlay, log each `ServerMsg` type with an ink/vermilion/jade colour key and a byte count, so the JSON full-state snapshot size is visible while you play and can be optimized.
57. **Add a `scripts/repl.mjs` for driving a live server interactively** — a small REPL that connects as a bot and lets you send `cast`, `input`, `npc`, `craft`, and `buy` by typing, so a designer can poke the Stone Guardian or a recipe without writing a script.
58. **Add a mob-placement debug view in the client** — behind `?debug=1`, draw every `MOB_SPAWNS` point and the 60-unit interest radius as an overlay so designers can eyeball spawn density and the boss arena without a full map edit.
59. **Add a telegraph debug renderer** — draw the raw `telegraph` shape (circle/cone/line/beam with sweep) as a wireframe overlay in the debug client, so the exact geometry the server uses is visible against the ink-wash ground art.
60. **Add a `--trace` mode to the server** — log every `cast`/`damage`/`death` with tick and entity id at trace level, filterable by entity, so a single boss kill or quest turn-in can be followed through the sim without the full event firehose.
61. **Publish per-tick and per-phase metrics to a Prometheus-style endpoint** — expose counters (snapshots sent, damage events, autosaves, dropped snaps, active sockets) as a scrape endpoint so Fly.io/Cloudflare dashboards can graph the single-process server's health.
62. **Add a sqlite query timer and slow-query log** — instrument `CharacterDb` and `contentdb.ts` writes so autosave or migration slowness surfaces as a named metric, guarding the authoritative server against a slow database blocking the tick.
63. **Track per-mob kill time and per-class DPS as a metric** — extend the soak kill log into a recorded metric so the team can see if a Talisman Master out-bursts the Sword Cultivator on the Stone Guardian or if a mob tier is over-tuned.
64. **Add an error auto-capture hook** — on any `tick error`/`handler error`/unhandled rejection, dump the last N events and the offending frame to a file, so the soak's "zero server errors" check becomes actionable instead of just red.
65. **Add structured logging with a request/connection id** — tag every log line with the socket id and a short correlation id so a multi-bot soak can be traced per connection, replacing the current free-text `[server!]` passthrough.
66. **Add a health probe for the R2/site workers** — a tiny `/healthz` in `site-worker` and `dl-worker` plus a CI ping after deploy, so the marketing site and the Electron launcher's download source are monitored end-to-end.
67. **Add a download-host smoke check to the release job** — after `publish-release.mjs`, fetch the just-published manifest and binary from R2 and verify checksums match `verify-signatures.mjs`, so a partial upload cannot brick the launcher.
68. **Add real-user telemetry opt-in in the launcher** — collect (with consent) install/update success, server URL, and client version, so the "Windows/macOS untested" and "audio unheard" limitations get real-world signal instead of staying blind spots.
69. **Generate the `ItemInfo`/`SkillDef`/`MobType` catalogues from `data.ts`** — codegen a typed catalogue JSON consumed by the client icons and tooltips so the 10 recipes, 4 rarities, and 6 slots stay in one source and the client cannot drift from the server.
70. **Generate the pictogram icon set from a single SVG source** — codegen the vector pictogram icons (skills, gear slots, coin/jade currencies, mobs) at multiple sizes from one master sheet, so the paper-scroll UI's iconography is consistent and recolourable for colour-assist.
71. **Generate the client's mob/class model parameter tables from `data.ts`** — emit the procedural model sizes and ink/vermilion/jade colours (Bamboo Spirit silhouette, Jade Serpent coils, Stone Guardian slabs) from server data so adding a mob does not require hand-editing `models/mobs.ts`.
72. **Generate a JSON Schema for `ClientMsg`/`ServerMsg` from the protocol** — derive validation schemas so the frame fuzzer and any future non-TS client check messages automatically, keeping the WebSocket JSON contract self-documenting.
73. **Generate the world map and atlas thumbnails from the zone data** — codegen the minimap/worldmap images from the 200x200 zone, spawn points, and place coordinates so the atlas art always matches the actual world instead of being hand-painted.
74. **Generate the daily-board and merit-seal copy from a single English strings table** — codegen the `daily` tasks, achievement `desc`, and title strings so the English-only rule and the `check-english.mjs` no-hanzi scan run against the source of truth, not scattered UI text.
75. **Pin the full toolchain with a lockfile in every package** — ensure server/client/launcher/website commit `package-lock.json` and CI uses `npm ci` (already partially done) so Node 22, Three.js, Vite, and Playwright versions are frozen and builds reproduce.
76. **Make `make-release.mjs` deterministic** — strip timestamps and sort generated files so two runs from the same commit produce byte-identical archives, enabling the release job to detect accidental drift.
77. **Add a build-id and version stamp to the client bundle** — bake the git SHA, `PROTOCOL_VERSION`, and `VERSION` into the built JS and show it on the login screen, so a support report can be matched to an exact reproducible build.
78. **Add a `verify-signatures.mjs` CI gate on every build artifact** — run the existing signature verification against the packaged launcher, Electron client, and R2 manifest so a tampered or corrupted artifact is rejected before publishing.
79. **Add a self-contained offline smoke for the packaged Electron launcher** — in CI, install the packaged launcher, point it at a local `dev-host.mjs` server and a fake download host, and assert it downloads, installs, and launches the client, closing the launcher-handoff loop.
80. **Add a `make check` aggregate that runs unit + bots + e2e + ui + english in one command** — a single developer-friendly entry point that sequences the fast tests first and fails early, so contributors get the whole gate locally without knowing each script's name.
