# Networking & Server Tech

1. **Binary snapshot codec with per-field versioning** — replace the full-state JSON snapshot with a length-prefixed binary buffer where each field (position, Qi, HP, hotbar cooldowns) carries a schema version tag, so the client and the 20Hz server can evolve the protocol independently without reserializing the whole valley every tick.
2. **Delta snapshot frames between keyframes** — send full player state once per second and tiny deltas (moved/rotated/cast) on the intervening ticks, cutting bandwidth for a 200x200 Cloudmist Valley with 27 mobs while keeping the server authoritative.
3. **Position quantization to grid steps** — quantize player coordinates to 0.25-unit steps and yaw to 8-bit buckets before packing, shrinking position payloads to a few bytes while preserving the feel of a 15-Qi dodge roll.
4. **Snapshot ring buffer for out-of-order recovery** — keep the last N binary snapshots per client in memory so a missed tick can be reconstructed instead of forcing a full-state resync when a WebSocket frame drops over Wi-Fi.
5. **Run-length plus dictionary compression for entity arrays** — compress repeated field values across the 27-mob list (most mobs idle between aggro) with a small static dictionary of field names, shrinking the average entity array on the wire.
6. **Client-predicted movement with server reconciliation** — let the Three.js client predict local movement between ticks and reconcile on the authoritative 20Hz correction, so a Sword Cultivator's dodge roll feels instant while the server stays the source of truth.
7. **Interpolation buffer keyed to tick numbers** — stamp every snapshot with a monotonic tick id so the client can interpolate between the last two received frames and hide jitter without trusting wall-clock time.
8. **Compact typed messages instead of JSON object keys** — replace string-keyed JSON (`{"kind":"damage","amount":12}`) with a message-table opcode plus fixed-order fields, cutting per-cast and per-damage event size across every skill in the valley.
9. **Snapshot field mask per entity type** — send only the fields a given entity uses (mobs skip Qi/gear/wallet, players skip leash/rarity), so a Stone Hound and a Player no longer share one fat schema on the wire.
10. **Protocol negotiation on connect with fallback** — the client advertises supported codec versions in the WebSocket handshake and the server downgrades to today's JSON snapshot for old Electron launchers, keeping rollouts reversible.

11. **Server-side speed and teleport validation** — clamp per-tick movement to a max speed derived from the class's base move plus any slow, rejecting a client that reports a Jade Serpent's lunge-worth of travel in one tick without a knockback.
12. **Cooldown enforcement for the 15-Qi dodge** — track the 1.5s dodge cooldown and 15-Qi cost authoritatively so a client cannot roll on every tick or roll with zero Qi, since the dodge is the primary evasion tool against Stone Guardian telegraphs.
13. **Qi spend accounting per skill** — the server deducts each skill's exact Qi cost and rejects casts that would drive the 100-point pool negative, closing the classic infinite-cast hole without trusting the client's reported pool.
14. **Input rate limiter on cast messages** — cap the number of `cast` messages per second per connection to a sane maximum so a modified client cannot spam Fire Talisman faster than its cooldown, and log the offending socket id.
15. **Server-side click/AFK heuristic** — flag a client whose cast timestamps are machine-perfectly periodic (exactly 1.5s dodge every time) as a possible script rather than banning on a single fast action, feeding a warning-only mist mark in the merit panel.
16. **Memory integrity is explicitly out of scope** — document that anti-cheat stops at input/speed validation because the client runs plain WebGL/JS where memory reads are undetectable server-side; spend effort on authoritative simulation instead of a doomed memory scanner.
17. **Boss telegraph intent validation** — verify a player's damage against the Stone Guardian only lands when a telegraph has resolved, preventing a spoofed client from hitting the boss during its cone/line/beam windup frames.
18. **Wallet and gear mutation guard** — treat every `wallet` and `inventory` change as a server-derived event (quest reward, shop purchase, recipe craft) and reject client-initiated writes, so a tampered client cannot mint jade or equip a 4th-rarity item it never owned.
19. **Replayable input log for adjudication** — record each client's validated inputs (move/cast/roll) into a bounded per-session ring so a reported speed-hacker can be reviewed by replaying their inputs through the authoritative sim, not by trusting a screenshot.
20. **Consistent server time base** — stamp every client action with the server's monotonic tick, never the client clock, so cooldown and speed checks cannot be defeated by rewinding a local clock or spoofing timestamps.

21. **Grid-partitioned interest cells over the 200x200 zone** — split Cloudmist Valley into fixed cells (e.g. 20x20) and send a player only the entities in their cell plus one ring of neighbors, so a player at spawn (0,-80) never receives the whole 27-mob state.
22. **Fog-of-war visibility gated by the mist palette** — tie the existing heavy fog and layered mountains to interest range so entities beyond the fog line are not even networked, matching what the player can see and saving bandwidth near the shrine.
23. **Per-player relevance radius tuned to class** — a Talisman Master's ranged attacks get a slightly wider interest radius than a Sword Cultivator's melee reach, so a ranged class sees the mobs it can actually hit at the pond edge.
24. **Boss telegraph broadcast to a widened radius** — when the Stone Guardian starts a slam or rotating beam, widen the interest radius for its telegraph and damage events so players just outside the normal circle still see the danger they could dodge into.
25. **Rare spawn interest push** — push Old Whisker's spawn and position as a high-priority interest message to nearby players even when idle, so a rare hunt in the mist does not depend on walking directly into its cell.
26. **Interest priority queue for chat and quests** — prioritize quest NPC dialogue (Elder Lin, Wu, Tao, Hao, Mei, Fen) and System chat lines over ambient mob movement when the snapshot budget is tight, keeping story prompts responsive.
27. **Mob idle state compression under interest** — mobs outside a player's combat radius still exist in the interest set but send only position updates at reduced frequency, so 27 idle mobs do not spam a player who is just reading the daily board.
28. **Entity removal on interest exit** — send an explicit `entity_leave` message when a player walks out of range so the Three.js scene despawns a Fox Spirit cleanly instead of freezing it mid-animation at the interest boundary.
29. **Spatial hash for interest queries at 20Hz** — index living entities in a spatial hash keyed by cell so the 20Hz interest pass is O(entities-in-range) rather than O(all entities), keeping the single-process server responsive at the level-20 cap.
30. **Interest-aware audio/particle gating client-side** — the client only spawns particles and (future) audio for entities inside its interest set, preventing a distant Stone Guardian slam from triggering a photosensitive-unsafe full-screen flash.

31. **Named shards of the single zone** — run multiple copies of Cloudmist Valley as numbered shards ("Cloudmist-1", "Cloudmist-2") sharing one server binary, so a growing player count is handled by adding a zone process rather than enlarging one 200x200 world.
32. **Shard selection at character enter** — the launcher/website assigns a shard at login based on population and lets players switch at the plaza, reusing the spawn-near-(0,-80) relocation path for the transfer.
33. **Boss arena instancing for the Stone Guardian** — instance the Stone Guardian fight per party so a group does not have to contest the boss with an unrelated player, while the open valley outside stays seamless.
34. **Dungeon instance seeds from the lotus shrine** — add an instanced interior entered from the shrine, generated per-party with its own mob set (Lotus Toads, Stone Hounds) so instance state does not pollute the open world.
35. **Instance ownership and lifetime** — an instance is owned by its party leader, persists for a short idle grace period, and is torn down server-side when empty, so abandoned dungeons do not accumulate in the single Node process.
36. **Cross-shard chat via a shared channel** — keep a lightweight cross-shard chat channel (a worker relay or shared buffer) so the daily board and friend chat work across "Cloudmist-1" and "Cloudmist-2" without merging world state.
37. **Shard-local economy with shared wallet** — coin/jade in the wallet sync across shards but shop stock and daily board entries are shard-local, preventing cross-shard market arbitrage in a game with no trading yet.
38. **Boss respawn and rare timers per shard** — the Stone Guardian respawn and Old Whisker rare timer are tracked per shard instance, so two shards do not fight over one shared global spawn clock.
39. **Instance cap per server process** — cap concurrent instances and entities per Node process (e.g. total mobs across shards) so the single-process, single-zone limitation is respected until a real multi-process shard layer exists.
40. **Graceful shard draining** — a shard can enter "draining" mode that stops new joins and lets players finish Elder Lin's chain before migrating, enabling zero-downtime deploys of the Node server.

41. **WebSocket gateway in front of the zone server** — a Cloudflare Workers / Durable Object edge layer terminates WebSocket connections and routes each client to the correct shard, so the authoritative Node process is not the connection front line.
42. **Sticky routing by shard assignment** — once a player is assigned to Cloudmist-2, the gateway pins their connection to that shard process for the session so their entity state does not bounce between processes.
43. **Health-based shard assignment at login** — the gateway samples each shard's entity count and tick latency and sends a new player to the least-loaded shard, using a simple round-robin fallback when metrics are stale.
44. **Backpressure from the tick loop** — if the 20Hz tick loop falls behind, the server drops non-critical snapshot deltas for far-interest entities first rather than queueing unboundedly, keeping the authoritative sim ahead of client demand.
45. **Message batching per client per tick** — coalesce multiple small events (several `damage` lines from one AoE) into a single WebSocket frame per tick so a Talisman Master's Fire Talisman AoE does not burst N separate writes.
46. **Worker-thread offload for snapshot encoding** — move binary snapshot encoding to a Node worker thread (or use msgpack/struct packing) so the main event loop spends its 20Hz budget on simulation, not serializing 27 mobs.
47. **Connection accept queue with graceful queueing** — when a login surge hits, queue new connections briefly and send a paper-scroll "Entering the Valley..." message instead of dropping them, keeping the 200x200 zone stable under load.
48. **Idle connection eviction** — after a configurable idle timeout with no input, the server pings and then drops the socket while persisting the character, freeing a slot for an active player and logging the disconnect.
49. **Latency-adaptive send coalescing** — the server groups positional updates and flushes them at a cadence matched to the client's observed round-trip time, so a high-latency player gets fewer, larger frames and a low-latency one gets crisp 20Hz updates.
50. **Load metrics exposed for the website** — publish shard population and tick health as a tiny JSON endpoint on the Cloudflare Worker so the website can show "Cloudmist-1: full" before a player picks a shard.

51. **Resume token in the WebSocket handshake** — issue a short-lived resume token on disconnect so a client can rejoin its in-progress session and reattach to its entity in Cloudmist Valley instead of respawning at the plaza.
52. **Server-side entity persistence across disconnects** — keep a disconnected player's character (position, Qi, HP, wallet, 30-slot bag) in memory and in node:sqlite for a grace window, so a brief Wi-Fi drop does not roll back quest or mob progress.
53. **Reconnect grace for the Stone Guardian fight** — if a player drops mid-boss, hold their slot in the instance for a short window so they can rejoin the 3-phase fight without losing contribution to the enrage timer.
54. **Snapshot-on-disconnect checkpoint** — write the last authoritative snapshot to sqlite at disconnect so a resumed client is seeded with exact position and cooldowns rather than a stale pre-drop state.
55. **Client-side reconnect state with countdown** — on socket loss the Three.js client shows a paper-scroll "Connection to the mist severed — retrying" overlay with a countdown and disables input, so the player is not fighting ghosts locally.
56. **Deterministic input replay for debugging** — store each session's validated inputs with tick stamps so a crash can be reproduced by replaying inputs through the authoritative sim headlessly, matching the "tested headless only" limitation.
57. **Idempotent command IDs** — stamp every cast/roll/use with a client-generated monotonic id the server dedupes, so a retried command after a reconnect cannot double-cast Meridian Surge or double-spend a 15-Qi dodge.
58. **Replay for combat balance tuning** — record boss fight inputs and outcomes to replay a Stone Guardian kill and measure telegraph dodge rates and Qi spend, feeding the same deterministic log used for adjudication.
59. **Spectator replay of recent fights** — later, let a player request a short server-replayed clip of a duel or boss kill rendered by the client's own Three.js scene, using the input log rather than raw pixels.
60. **SQLite WAL for crash recovery** — enable WAL mode on node:sqlite so a hard server crash leaves the last-committed wallet/quest/inventory state recoverable, minimizing what a reconnect must resync.

61. **Per-connection command rate budget** — enforce a token bucket per socket for all player commands (cast, roll, use, interact) so a flood of Fire Talisman casts is throttled before it reaches the sim, with overflow dropped and logged.
62. **Chat rate limit and anti-spam** — cap chat messages per second and de-duplicate repeated lines so the paper-scroll chat and daily board broadcast channels stay readable and cannot be spammed.
63. **Login/enter handshake throttle** — limit enter/character-select requests per IP to blunt account-creation and shard-pick abuse, since there is no password/account system yet to rate-limit against.
64. **Movement update cap independent of input** — accept client input at high rate but only apply and rebroadcast position at the 20Hz tick cadence, so a spammy client cannot force extra snapshot writes for its own entity.
65. **Quest/daily claim rate guard** — rate-limit the `daily` board and NPC claim messages so a scripted client cannot re-claim Wu's or Fen's daily reward repeatedly in one second.
66. **Shop purchase transaction guard** — wrap each shop buy and recipe craft in a short server-side lock so a double-click cannot spend coin twice or craft the same recipe twice from one set of materials.
67. **WebSocket frame size cap** — reject messages over a max byte size and close oversized frames, preventing a malicious client from sending a megabyte "cast" payload that stalls JSON parsing on the 20Hz loop.
68. **Graduated rate-limit response** — escalate from dropping a command to a warning System line to a temporary "mist-bound" throttle to a socket close, mirroring the game's ink-wash tone rather than a hard ban on first offense.
69. **Distinct limits per message kind** — give chat, cast, and movement separate budgets (a Physician healing rapidly is legitimate, chat spam is not), so limits do not collide with valid high-APM play near the Stone Guardian.
70. **Rate-limit metrics to the website worker** — surface per-shard command rate and drops as counters the Cloudflare Worker can read, so operators can see a spam spike on Cloudmist-1 before it degrades the tick.

71. **Static collider grid for the valley** — bake the 200x200 valley's obstacles (pond edges, shrine walls, paifang posts, rocks) into a server-side grid so the server can clamp positions and stop players from walking through the lotus pond.
72. **Collider placement aligned to the client's procedural models** — define collision from the same procedural placement data the Three.js client uses to build models, so a stone wall that blocks on the server is the exact wall the client renders in ink outline.
73. **Server-side wall clamping on movement apply** — after each authoritative movement update, clamp the final position against the collider grid so a client reporting a wall-crossing position is corrected rather than trusted.
74. **Telegraph placement validated against colliders** — reject a Talisman Master placing an AoE inside a solid rock or across the pond if the server colliders say the location is impassable, keeping ground-target skills honest.
75. **Mob pathing against the collider grid** — give the 27 mobs a simple server-side waypoint path that avoids colliders, so a Jade Serpent or Stone Hound does not glide through a wall the player cannot pass.
76. **Boss arena boundary enforcement** — during the Stone Guardian fight, clamp players to the arena floor's collider bounds so the cone/line/beam dodging happens inside the intended ring and no one dodges through the shrine wall.
77. **Dodge roll collision stop** — when the 15-Qi dodge would cross a collider, stop the roll at the obstacle and refund a portion of Qi, so a roll into a wall is a predictable, fair result rather than a clip through geometry.
78. **Height and slope simplification** — model the valley's layered-mountain elevation as a simple passable/impassable plus shallow-slope heightfield rather than full 3D collision, keeping the 20Hz server cost low while blocking the few real walls.
79. **Collision sync as part of the protocol handshake** — send the collider grid or its hash to the client at connect so both sides validate against the same layout, catching a stale Electron launcher with an outdated collider set.
80. **Graceful fallback when colliders are absent** — until server-side collision ships, keep a soft mode where the server logs out-of-bounds positions and clamps to the 200x200 zone border, so the known "no server-side collision" limitation degrades to a warning, not a teleport exploit.
