# Deploying the website

The site is a single Cloudflare Worker named `swordandseal-website` (`website/wrangler.toml`) that serves every
page and asset from one inlined bundle: `website/dist-worker/worker.mjs`. There is no static host and no build step
on Cloudflare's side — whatever is uploaded is exactly what `node website/build.mjs` produced.

## One command

```powershell
npm run check:site     # build + worker probe + link check. Nothing is uploaded.
npm run deploy:site    # the same gate, then upload and verify the live site
```

`deploy:site` runs, in order:

1. `node website/build.mjs` — rebuild all pages into `website/dist/` and the Worker bundle into `website/dist-worker/`.
2. `node website/scripts/probe-worker.mjs` — import the built Worker and call it in-process: every page must answer
   200 with the expected content, an unknown path must answer 404, the security headers and cache policy must be
   present, the stylesheet referenced by the pages must exist, the sitemap must list the new pages, and `www` must
   redirect to the apex.
3. `node website/scripts/linkcheck.mjs` — every internal reference across every built page.
4. `npx wrangler deploy` from `website/`.
5. `node website/scripts/live-check.mjs` — fetch `https://swordandseal.com` and assert the live pages carry the
   current `VERSION` (retrying for a few seconds while the Worker propagates).

`npm run deploy:site -- --dry-run` does the gate and a local `wrangler --dry-run` bundle without uploading.
`npm run check:site` is the gate alone, and `npm run live:site` is the live check alone.

## Credentials

The deploy needs Cloudflare auth, and the token needs **Workers Scripts: Edit** on the account (plus permission to
edit the `swordandseal.com` zone for the routes). Either:

```powershell
$env:CLOUDFLARE_API_TOKEN = "<token>"
$env:CLOUDFLARE_ACCOUNT_ID = "<account id>"   # optional when the token belongs to one account
npm run deploy:site
```

or create a session once:

```powershell
cd website
npx wrangler login     # opens a browser for the Cloudflare login
```

`deploy:site` detects `CLOUDFLARE_API_TOKEN` or an existing wrangler session and refuses to run without one, so a
half-configured machine cannot report a deploy that never happened.

## What a release changes on the site

- `/changelog` gains the new version and its anchors (`#v0-6-0`) — the launcher and the game deep-link into these.
- `/roadmap` updates its shipped list and the "next" column.
- `/news` gets its seed posts from the same `CHANGELOG.md` parse.
- The footer version (from `VERSION`) moves on every page.
- `sitemap.xml` and the Worker's route table are regenerated by the build.

## Troubleshooting

- **The live check fails but wrangler said success.** Workers propagate in seconds, but the live check allows ~30 s
  of retries. If it still fails, run `npm run live:site` again; check the Worker is bound to the routes in
  `website/wrangler.toml` (Dashboard → Workers & Pages → swordandseal-website → Settings → Domains & Routes).
- **`www` does not redirect.** The `www` route needs a proxied (orange-cloud) DNS record, as noted in `wrangler.toml`.
- **A page answers with old content.** Confirm the build ran in the same command (the deploy always rebuilds first);
  Cloudflare caches HTML for a short time only — hard-reload once.
- **Unknown route returns the home page.** The Worker's 404 branch depends on the generated route table; re-run the
  build rather than editing `dist-worker/worker.mjs` by hand (it is generated).

## Current state (2026-10-31)

Version **0.6.0** is live at https://swordandseal.com — including `/roadmap`, `/changelog`, `/status`, `/press`,
`/devlog` and the first-hour guide on `/support`. It was published with `npm run deploy:site` (Worker version
`af81e6bd-7127-4a7f-aeb8-c694d2a35861`, 1622.60 KiB uploaded / 1051.06 KiB gzip) and confirmed by
`npm run live:site`.

Before that, the live site had been stuck at 0.3.0 — the deploy was manual and nobody had run it. Use the commands in
this file for every site change from now on; `check:site` is safe to run anywhere and catches a broken build before
it can be published.
